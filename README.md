# Мониторинг госзакупок 44-ФЗ и 223-ФЗ — инструкция

Готовый стартовый проект для публичного GitHub Pages. Проект ориентирован на российские государственные и корпоративные закупки. Публикуются заголовки и ссылки, не полные тексты. Статусы актов не устанавливаются автоматически. Архив ограничен 10 000 записей, дубликаты удаляются по URL без рекламных параметров. Разные публикации об одном событии сохраняются.

## 1. Размещение через браузер
1. Зарегистрируйтесь на https://github.com и подтвердите почту.
2. Создайте публичный репозиторий `legal-monitor`, ветка `main`. Не добавляйте секреты или персональные сведения.
3. Распакуйте архив. Загрузите файлы и папки в корень репозитория через Add file → Upload files. Обязательно проверьте наличие скрытой папки `.github/workflows/monitor.yml`: если загрузчик её пропустил, создайте файл через Add file → Create new file, указав полный путь `.github/workflows/monitor.yml`, и вставьте его содержимое из архива.
4. Settings → Pages → Build and deployment → Source → GitHub Actions.
5. Settings → Actions → General: разрешите используемые Actions; при необходимости разрешите Read and write permissions. Право contents: write также задано в workflow. Ветка main должна допускать коммиты бота.
6. Actions → Legal monitor → Run workflow → main → Run workflow. Первый автоматический запуск при загрузке может завершиться ошибкой до настройки Pages; повторите вручную.
7. Откройте завершившийся запуск, проверьте collect и deploy. Ссылка на сайт появится в Settings → Pages и в deploy. Обычно https://ВАШ-ЛОГИН.github.io/legal-monitor/.

## 2. Проверка
- В Actions проверьте шаг тестов и журнал `python collect.py`: число успешных источников и записей.
- В репозитории откройте docs/news.json: updated, sources, items. Каждый источник имеет ok и count либо error. Нулевой count при ok возможен из-за фильтра.
- На сайте попробуйте поиск и фильтры, откройте оригинал новости. Сверьте дату и заголовок с источником.
- Повторите ручной запуск: одна ссылка не должна появиться дважды. Проверяйте изменение времени последней попытки.
- Через 30–60 минут проверьте плановый запуск (расписание UTC, минуты 07 и 37; возможны задержки). GitHub может отключить расписание публичного репозитория после 60 дней отсутствия активности; при необходимости включите вновь.
- При полном отказе источников архив сохраняется, диагностическая страница публикуется, workflow помечается ошибкой. При частичном отказе смотрите состояние источников на сайте.

## 3. Локальная проверка (не обязательна)
Установите Python 3.12. В терминале в папке проекта:
```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python collect.py
python -m http.server 8000 --directory docs
```
Откройте http://localhost:8000. Не открывайте index.html двойным щелчком: браузер может блокировать загрузку JSON. Остановить сервер — Ctrl+C.

## 4. Добавление источников
Редактируйте sources.json через GitHub (значок карандаша). Для RSS добавьте объект с name, kind, type=`rss`, url (именно URL ленты), enabled=true. Для HTML используйте type=`html`, url страницы и selector CSS, указывающий на ссылки с заголовками, например `article h2 a`. Для публичного Telegram — type=`telegram`, url=`https://t.me/s/ИМЯ_КАНАЛА`. Включайте только разрешённые к сбору источники. HTML-источник ГАРАНТ отключён до проверки селектора и условий использования; два Telegram-канала включены. Для новых источников обязательно задавайте procurement_only: true. Для иных соцсетей используйте разрешённый RSS/API; универсального доступа к закрытым аккаунтам нет. API-адаптеры не входят в эту версию. Для дополнительного отбора можно добавить keywords (любое совпадение). Законы, темы и типы новостей определяются в procurement.py. Не добавляйте токены в публичный JSON.

Стартовые источники: профильный RSS КонсультантПлюс https://www.consultant.ru/rss/fks.xml (адрес опубликован на https://www.consultant.ru/law/rss/), общие RSS законодательства и законопроектов, публичные Telegram-каналы https://t.me/s/gis_eiszakupki и https://t.me/s/minfin. Прямой парсер официального опубликования, ФАС и сайта ЕИС не реализован. ГАРАНТ добавлен в отключённом виде. Проверьте доступность, разрешения и результаты каждого источника в GitHub Actions; сетевой сбор не тестировался. Не обходите ограничения.

## Тематическая настройка
- По умолчанию исключаются нерелевантные новости, правила в procurement.py.
- Метки 44-ФЗ и 223-ФЗ могут присутствовать одновременно; при отсутствии явного основания новость получает общую метку.
- Тип новости определяется эвристически, не подтверждает юридический статус. Темы могут пересекаться.
- Классификация учитывает заголовок и RSS-аннотацию либо текст публичного Telegram-поста, но хранит только заголовок/краткий фрагмент, ссылку и метаданные.
- Если обновляете старый репозиторий, замените файлы новым архивом; прежние записи без меток будут исключены из новой подборки. Не забудьте сохранить резервную копию старого архива.
- При проверке попробуйте фильтры 44-ФЗ, 223-ФЗ, Нацрежим и Законопроект. Проверьте, что публикация о двух законах видна в обоих фильтрах. Тесты: 10 локальных, включая отбор и классификацию.

## 5. Ошибки и обслуживание
- 403/429: проверьте правила, доступность, уменьшите частоту; не обходите ограничения.
- Нет RSS: проверьте URL и формат. HTML: уточните CSS-селектор. Telegram: доступность публичной страницы и разрешение на сбор.
- Ошибка git push: проверьте права Actions и защиту ветки, затем повторите запуск.
- Ошибка Pages: проверьте Source = GitHub Actions и разрешения pages/id-token, environment github-pages.
- При смене страны замените sources.json и подпись страны в docs/index.html. Классификация настроена на русскоязычные ключевые слова.
- Бесплатность предполагает публичный репозиторий, стандартный runner и соблюдение лимитов GitHub. Сайт публичный, не предназначен для конфиденциальных данных. ChatGPT и платный API не нужны.
